# Regression fixtures — markdown chunking + wide CSV

Generated by `halo-local/temp/gen-regression-fixtures.mjs` for WP-D2 (task 283b8f76).
These files exist to **visually verify** fixes to `src/renderer/lib/markdown-chunks.ts`
(WP-G, fixing the 8 counterexamples found in
`halo-local/temp/perf-round2-wpe-kimi3-chunk-counterexamples.md`) and to document
one known-uncovered performance dimension (wide CSV). They are not unit tests —
open each one in Halo's canvas viewer and compare what you see against "expected"
below. If you're reading this without that context: someone found that
`markdown-chunks.ts` splits large markdown documents into pieces for virtualized
rendering, and some kinds of markdown render differently when split than when
rendered whole. These files are built large enough (all > 128,000 characters,
the threshold in `MarkdownViewer.tsx:96`) to actually trigger that code path —
a small file proves nothing here, because below the threshold the document
renders through the original, unaffected code path.

Regenerate with `node halo-local/temp/gen-regression-fixtures.mjs` from the repo
root — it's a plain Node script, no build step, and prints a `simulateSplit()`
verification (a read-only copy of the real algorithm) showing exactly which
chunk each interesting piece of text lands in.

## Why these are safe to test right now

Every `.md` fixture above is built so the interesting content sits in the
**first** ~10,000–20,000 characters, with a large block of unrelated filler
paragraphs appended afterward purely to push the file's total length past the
128,000-character threshold (filler text is repeated "alpha bravo charlie..."
placeholder words — it carries no meaning, don't read it). You do not need to
scroll through the whole file to check the "Look at" column above; the
generator's console output states which chunk index each interesting string
landed in for `details-container.md`, `html-comment.md`, `footnotes.md`,
`nested-list.md`, and `indented-code.md` — rerun the script if you need that
printed again.

## `cjk-mixed-log.md` — 中文为主 + 粘贴产物（后补）

**它测的不是某一条反例，而是一整类文档的"长相"。** 前面那些 fixture 都是为单条缺陷定做的合成
素材，干净、只含目标特征；而真实的对话记录与数字人 memory 长的是另一个样子：中文正文里夹着粘贴
的堆栈、日志围栏、抓来的 HTML 片段、行内代码里的 JSX 与正则字符类——**本轮全部误判形态的天然
聚集地**。这一轮最严重的一次回归（43 个真实文档里 11 个虚拟化被静默关闭）就是被这种形态触发的，
而当时所有 fixture 和单测都是绿的。

- **规模**：150,360 字符 / 326,284 字节，比值 **2.17**。
  顺带演示一个真实踩过的坑：**分块阈值比的是字符数，不是字节数**。用 `wc -c` 或 `find` 的大小去
  筛语料，本仓会从 43 个"超阈值文档"变成 72 个，多出来的 29 个其实根本没过阈值。
- **期望**：切成数十块（当前 36 块），且没有任何块以空白开头。
- **算失败**：塌成 1 块，或块数掉到个位数——说明某条护栏又开始误判，虚拟化被静默关掉了。
- **它是真护栏，不是摆设**：拿第一轮的护栏版本（HTML 开标签行内匹配、不处理自闭合）跑同一份文件，
  会塌成 **1 块**；当前版本 36 块。

**为什么不直接拿运行时的 memory 文件当语料**：产品真正在增长的 memory 在 `~/.halo/spaces/**`，
是本机绝对路径、跨机器不可移植，做不了固定门禁（本团队就有成员跑在别人机器上）。所以把那个
文档形态固化成这份 fixture，而不是指向一条只在某台机器上成立的路径。
