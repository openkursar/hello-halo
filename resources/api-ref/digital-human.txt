## digital-human — create, run and configure digital humans
covers: install and uninstall, pause and resume, manual trigger, schedule and
        user config, chat with a digital human, run history and activity
not here:
  binding a digital human to an IM chat -> channels
  files a digital human produced -> workspace
  installing from the app store -> store
  knowledge a digital human reads -> knowledge-base

operations on this page:
  GET    /api/apps                                                   List digital humans (and other installed apps) in a space
  GET    /api/apps/<appId>                                           Get one installed digital human (or other app) by id
  DELETE /api/apps/<appId>                                           Soft-delete (uninstall) a digital human; recoverable via reinstall

GET    /api/apps                                                   List digital humans (and other installed apps) in a space
     curl -s "$HALO_API_URL/api/apps" -H "Authorization: Bearer $HALO_API_TOKEN" | head -c 4000
     # out: {success:true,data:[{id,specId,spaceId,spec,status,userConfig,userOverrides,permissions,installedAt,lastRunAt?,lastRunOutcome?,errorMessage?}]}  — userConfig/spec.mcp_server.env/headers values are redacted to "[redacted]", keys are preserved
     # note: Optional query: ?spaceId=, ?status=. Without ?status, uninstalled apps are excluded by default.

GET    /api/apps/<appId>                                           Get one installed digital human (or other app) by id
     curl -s "$HALO_API_URL/api/apps/<appId>" -H "Authorization: Bearer $HALO_API_TOKEN"
     # out: {success:true,data:InstalledApp|null}  — same shape as GET /api/apps entries, redacted the same way

DELETE /api/apps/<appId>                                           Soft-delete (uninstall) a digital human; recoverable via reinstall
     # note: reversible — can be undone or corrected afterward.
     curl -sX DELETE "$HALO_API_URL/api/apps/<appId>" -H "Authorization: Bearer $HALO_API_TOKEN"
     # out: {success:true}
     # note: No body. There is a ?purge=true query param but it is currently a no-op (ignored by the handler) — it does not delete on-disk data. This is reversible (see POST /:appId/reinstall). For permanent, unrecoverable deletion use delete_automation_app instead.

GET    /api/apps/<appId>/activity                                  Get the activity/run-history entries for a digital human
     curl -s "$HALO_API_URL/api/apps/<appId>/activity" -H "Authorization: Bearer $HALO_API_TOKEN" | head -c 4000
     # out: {success:true,data:[{id,appId,runId,type:"run_complete"|"run_skipped"|"run_error"|"milestone"|"escalation"|"output",ts,content,userResponse?}]}
     # note: Query params: limit (max entries), before (only entries with ts older than this epoch ms)

GET    /api/apps/<appId>/available-skills                          List skills this digital human can load (global + space-local)
     curl -s "$HALO_API_URL/api/apps/<appId>/available-skills" -H "Authorization: Bearer $HALO_API_TOKEN" | head -c 4000
     # out: {success:true,data:[{name,description,scope:"global"|"space",dirName,path}]}
     # err: 404-equivalent = {success:false,error:"App not found or has no space"} — the app must have a spaceId

POST   /api/apps/<appId>/chat/clear                                Clear a digital human's chat history
     !! DESTRUCTIVE: cannot be undone. Confirm with the user in plain language before running this.
     curl -sX POST "$HALO_API_URL/api/apps/<appId>/chat/clear" \
          -H "Authorization: Bearer $HALO_API_TOKEN" \
          -H "Content-Type: application/json" \

     # body: {"spaceId": "<spaceId — a uuid from GET /api/spaces>"}
     # out: {success:true}
     # note: spaceId is required even though the app is already scoped to one. Optional conversationId clears one specific session instead of the default one.

     # out: {success:true,data:{sessionsClosed:number}}
     # note: Interrupts any in-flight turn. Conversation history is preserved.

POST   /api/apps/<appId>/escalation/<entryId>/respond              Answer a digital human's pending question (it stopped to ask a human before continuing)
     !! DESTRUCTIVE: cannot be undone. Confirm with the user in plain language before running this.
     curl -sX POST "$HALO_API_URL/api/apps/<appId>/escalation/<entryId>/respond" \
          -H "Authorization: Bearer $HALO_API_TOKEN" \
          -H "Content-Type: application/json" \
          -d '{"choice":"approve","text":"optional free-text explanation"}'
     # body: {"choice": "approve", "text": "optional free-text explanation"}
     # out: {success:true}
     # note: choice and text are both optional (send whichever the pending question asked for). Find the pending entryId via GET /:appId/activity (type:"escalation") or by app.status==="waiting_user". This is the human decision it was waiting for — answer with the user's actual input, never a guessed one, and there is no way to un-answer it afterward.

-----------------------------------------------------------------------
$HALO_API_URL, $HALO_API_TOKEN and $HALO_SPACE_ID are already set in your Bash
  environment. Copy commands as-is; never expand or print those variables.
Replace only <angle-bracket> placeholders. Get real ids from a list call above.
Read the response body and check "success". HTTP 200 alone does not mean it
  worked - many failures return 200 with {"success":false}.
Pipe long responses through `| head -c 4000` so you do not flood your context.
A POST that timed out may still have taken effect. List before you retry.
Waiting on something? Back off (2s, then double), give up after 5 tries and
  tell the user it is still running.
Large or binary files do not go through this API - use Read / Write / Bash.
403 = the endpoint exists but is closed to me in this build. Tell the user to
  do it in the Halo app. Do not tell them Halo cannot do it.
404 with a "code" field = my path is wrong. 404 without one = the id is wrong.
Only call paths listed on this page or in the index. Never write one from
  memory. If this page has left your context, call halo_api_ref again.
Full index of every endpoint: {{API_REF_INDEX_PATH}}/index.txt
  grep -i "<keyword>" {{API_REF_INDEX_PATH}}/index.txt
Not listed here does NOT mean not supported — that is a real, deliverable
  answer, not a failed search. Grep the index before you say "Halo can't do that".
