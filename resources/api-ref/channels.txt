## channels — inbound IM channels and outbound notifications
covers: connect and disconnect IM channels, bind a chat to a digital human,
        list bound sessions, configure and test outbound notification channels
not here:
  the digital human on the other end of a channel -> digital-human
  model providers and API keys -> settings

operations on this page:
  POST   /api/apps/<appId>/im-chat/clear                             Clear a digital human's chat history in a bound IM chat   !! destructive
  POST   /api/apps/<appId>/im-chat/stop                              Stop a digital human's in-progress reply in a bound IM chat (keeps history)
  GET    /api/im-channels/permission-defaults                        Get this build's default guest-access permission settings for new IM instances
  GET    /api/im-channels/providers                                  List available IM channel provider types and their config fields
  POST   /api/im-channels/reconnect                                  Reconnect one IM channel instance
  POST   /api/im-channels/reload                                     Reload all IM channel instances from saved config
  GET    /api/im-channels/status                                     Get connection status for all IM channel instances, or one via ?instanceId=
  GET    /api/im-sessions                                            List known IM contacts/chats bound to digital humans, optional ?appId= filter
  POST   /api/im-sessions/remove                                     Remove a chat binding from the IM session registry
  POST   /api/im-sessions/set-custom-name                            Set a custom display name for a chat binding
  POST   /api/im-sessions/set-proactive                              Toggle whether a run's result is auto-pushed to this chat when it finishes

POST   /api/apps/<appId>/im-chat/clear                             Clear a digital human's chat history in a bound IM chat
     !! DESTRUCTIVE: cannot be undone. Confirm with the user in plain language before running this.
     curl -sX POST "$HALO_API_URL/api/apps/<appId>/im-chat/clear" \
          -H "Authorization: Bearer $HALO_API_TOKEN" \
          -H "Content-Type: application/json" \
          -d '{"spaceId":"<spaceId — a uuid from GET /api/spaces>","channel":"wecom","chatType":"direct","chatId":"<chatId — from GET /api/im-sessions>"}'
     # body: {"spaceId": "<spaceId — a uuid from GET /api/spaces>", "channel": "wecom", "chatType": "direct", "chatId": "<chatId — from GET /api/im-sessions>"}
     # out: {success:true}
     # note: All four body fields are required, 400 otherwise. chatType is "direct" or "group".

POST   /api/apps/<appId>/im-chat/stop                              Stop a digital human's in-progress reply in a bound IM chat (keeps history)
     curl -sX POST "$HALO_API_URL/api/apps/<appId>/im-chat/stop" \
          -H "Authorization: Bearer $HALO_API_TOKEN" \
          -H "Content-Type: application/json" \
          -d '{"channel":"wecom","chatType":"direct","chatId":"<chatId — from GET /api/im-sessions>"}'
     # body: {"channel": "wecom", "chatType": "direct", "chatId": "<chatId — from GET /api/im-sessions>"}
     # out: {success:true,data:{stopped:boolean}}
     # note: chatType is "direct" or "group". Unlike im-chat/clear, this only aborts the current turn — the session and its history continue on the next inbound message.

GET    /api/im-channels/permission-defaults                        Get this build's default guest-access permission settings for new IM instances
     curl -s "$HALO_API_URL/api/im-channels/permission-defaults" -H "Authorization: Bearer $HALO_API_TOKEN"
     # out: {success:true,data:{defaultEnabled?,defaultGuestAccess?,defaultGuestPolicy?:{allowedTools?},ownerIdHint?,ownerSetupGuideUrl?} | null}

GET    /api/im-channels/providers                                  List available IM channel provider types and their config fields
     curl -s "$HALO_API_URL/api/im-channels/providers" -H "Authorization: Bearer $HALO_API_TOKEN" | head -c 4000
     # out: {success:true,data:[{type,displayName,description,direction,configFields:[{key,label,type,placeholder?,required?}],defaultConfig}]}
     # note: Schema only. No endpoint here creates an instance from it — the user creates instances in Settings > Message Channels. Schema only (field definitions and empty defaults) — no configured instance data or secrets.

POST   /api/im-channels/reconnect                                  Reconnect one IM channel instance
     # note: reversible — can be undone or corrected afterward.
     curl -sX POST "$HALO_API_URL/api/im-channels/reconnect" \
          -H "Authorization: Bearer $HALO_API_TOKEN" \
          -H "Content-Type: application/json" \
          -d '{"instanceId":"<instanceId — from GET /api/im-channels/status>"}'
     # body: {"instanceId":"<instanceId — from GET /api/im-channels/status>"}
     # out: {success:boolean,error?}
     # err: 400 if instanceId is missing. success:false with an error message if the instanceId is unknown.

POST   /api/im-channels/reload                                     Reload all IM channel instances from saved config
     # note: reversible — can be undone or corrected afterward.
     curl -sX POST "$HALO_API_URL/api/im-channels/reload" -H "Authorization: Bearer $HALO_API_TOKEN"
     # out: {success:true}
     # note: Use after a config change made through another route to apply it without restarting Halo. Stops and rebuilds any instance whose config changed — brief interruption, no data lost.

GET    /api/im-channels/status                                     Get connection status for all IM channel instances, or one via ?instanceId=
     curl -s "$HALO_API_URL/api/im-channels/status" -H "Authorization: Bearer $HALO_API_TOKEN"
     # out: {success:true,data:{id,type,enabled,connected,state?,appId,appName?,reason?,identityResolution?}[] | <single instance object>}
     # note: No credentials in this response. instanceId not found → {success:false,error}.

GET    /api/im-sessions                                            List known IM contacts/chats bound to digital humans, optional ?appId= filter
     curl -s "$HALO_API_URL/api/im-sessions" -H "Authorization: Bearer $HALO_API_TOKEN" | head -c 4000
     # out: {success:true,data:[{appId,channel,chatId,proactive,customName?,...}]}

POST   /api/im-sessions/remove                                     Remove a chat binding from the IM session registry
     # note: reversible — can be undone or corrected afterward.
     curl -sX POST "$HALO_API_URL/api/im-sessions/remove" \
          -H "Authorization: Bearer $HALO_API_TOKEN" \
          -H "Content-Type: application/json" \
          -d '{"appId":"<appId — a uuid from GET /api/apps>","channel":"wecom-bot","chatId":"<chatId — from GET /api/im-sessions>"}'
     # body: {"appId":"<appId — a uuid from GET /api/apps>","channel":"wecom-bot","chatId":"<chatId — from GET /api/im-sessions>"}
     # out: {success:true,data:{removed:boolean}}
     # note: removed:false means no matching session was found — not an error. Only removes display metadata (custom name, proactive flag); the chat re-registers itself on its next inbound message, message history is not stored here.

POST   /api/im-sessions/set-custom-name                            Set a custom display name for a chat binding

     curl -sX POST "$HALO_API_URL/api/im-sessions/set-custom-name" \
          -H "Authorization: Bearer $HALO_API_TOKEN" \
          -H "Content-Type: application/json" \
          -d '{"appId":"<appId — a uuid from GET /api/apps>","channel":"wecom-bot","chatId":"<chatId — from GET /api/im-sessions>","name":"Sales Team Chat"}'

     # err: 404 if no matching session exists yet.

POST   /api/im-sessions/set-proactive                              Toggle whether a run's result is auto-pushed to this chat when it finishes

     curl -sX POST "$HALO_API_URL/api/im-sessions/set-proactive" \
          -H "Authorization: Bearer $HALO_API_TOKEN" \
          -H "Content-Type: application/json" \
          -d '{"appId":"<appId — a uuid from GET /api/apps>","channel":"wecom-bot","chatId":"<chatId — from GET /api/im-sessions>","proactive":true}'
     # body: {"appId":"<appId — a uuid from GET /api/apps>","channel":"wecom-bot","chatId":"<chatId — from GET /api/im-sessions>","proactive":true}
     # out: {success:true} or {success:false,error}
     # err: 404 if no matching session exists yet — the chat must have messaged the digital human at least once.

POST   /api/notify-channels/test                                   Send a test notification through one configured channel
     # note: reversible — can be undone or corrected afterward.
     curl -sX POST "$HALO_API_URL/api/notify-channels/test" \
          -H "Authorization: Bearer $HALO_API_TOKEN" \
          -H "Content-Type: application/json" \
          -d '{"channelType":"wecom"}'
     # body: {"channelType":"wecom"}
     # out: {"success":true,"data":{...delivery result}}
     # note: channelType is one of: wecom, dingtalk, feishu, email, webhook.
     # note: This really delivers a message, so say so before using it.
     # note: It is not a way to send something the user dictated: the payload is a fixed test string and nothing you write can go into it. Use the notify_channel tool to send real content.
     # note: "No notification channels configured" = the user has not set one up yet.

POST   /api/wecom-bot/reconnect                                    Reconnect all configured WeCom bot instances

     curl -sX POST "$HALO_API_URL/api/wecom-bot/reconnect" -H "Authorization: Bearer $HALO_API_TOKEN"

GET    /api/wecom-bot/status                                       Check whether a WeCom bot channel is configured and connected

     # out: {success:true,data:{configured:boolean,enabled:boolean,connected:boolean}}

POST   /api/weixin-ilink/disconnect                                Clear WeChat iLink credentials for an instance and stop it
     # note: reversible — can be undone or corrected afterward.
     curl -sX POST "$HALO_API_URL/api/weixin-ilink/disconnect" \
          -H "Authorization: Bearer $HALO_API_TOKEN" \
          -H "Content-Type: application/json" \
          -d '{"instanceId":"<instanceId — from GET /api/im-channels/status>"}'
     # body: {"instanceId":"<instanceId — from GET /api/im-channels/status>"}

     # note: Can be restored by pairing again (request-qrcode) or by calling save-token with the same token.

POST   /api/weixin-ilink/save-token                                Set the bot token for an already-configured WeChat iLink instance
     # note: reversible — can be undone or corrected afterward.
     curl -sX POST "$HALO_API_URL/api/weixin-ilink/save-token" \
          -H "Authorization: Bearer $HALO_API_TOKEN" \
          -H "Content-Type: application/json" \
          -d '{"instanceId":"<instanceId — from GET /api/im-channels/status>","botToken":"..."}'
     # body: {"instanceId":"<instanceId — from GET /api/im-channels/status>","botToken":"..."}
     # out: {success:true} or {success:false,error}
     # note: Optional fields: baseUrl, accountId.
     # note: instanceId must already exist (created earlier in the Settings UI) — this route cannot create a new instance, only fill in its token.
     # note: Never echoes the token back in the response.
     # note: {success:false,error:"..."} when instanceId is not found in config.
     # note: Takes over that channel identity immediately — a wrong token silently hijacks it until corrected.

-----------------------------------------------------------------------
$HALO_API_URL, $HALO_API_TOKEN and $HALO_SPACE_ID are already set in your Bash
  environment. Copy commands as-is; never expand or print those variables.
Replace only <angle-bracket> placeholders. Get real ids from a list call above.
Read the response body and check "success". HTTP 200 alone does not mean it
  worked - many failures return 200 with {"success":false}.
Pipe long responses through `| head -c 4000` so you do not flood your context.
A POST that timed out may still have taken effect. List before you retry.
Waiting on something? Back off (2s, then double), give up after 5 tries and
  tell the user it is still running.
Large or binary files do not go through this API - use Read / Write / Bash.
403 = the endpoint exists but is closed to me in this build. Tell the user to
  do it in the Halo app. Do not tell them Halo cannot do it.
404 with a "code" field = my path is wrong. 404 without one = the id is wrong.
Only call paths listed on this page or in the index. Never write one from
  memory. If this page has left your context, call halo_api_ref again.
Full index of every endpoint: {{API_REF_INDEX_PATH}}/index.txt
  grep -i "<keyword>" {{API_REF_INDEX_PATH}}/index.txt
Not listed here does NOT mean not supported — that is a real, deliverable
  answer, not a failed search. Grep the index before you say "Halo can't do that".
