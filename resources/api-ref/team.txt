## team — teams of digital humans that work toward one goal together
covers: list, create and dissolve teams, edit name and goal, add, remove and
        re-brief members, collaboration topology, start and stop a run,
        schedules and other triggers, message or stop one member, run history,
        boards, conversations and produced files, save a temporary
        collaboration as a team
not here:
  one digital human on its own schedule -> digital-human
  installing a digital human to use as a member -> digital-human
  binding an IM chat to a team member -> channels
  assigning independent work inside this conversation -> use the spawn_agent tool

GET    /api/teams                                                  List saved teams, optionally only those owned by one space
     curl -s "$HALO_API_URL/api/teams" -H "Authorization: Bearer $HALO_API_TOKEN" | head -c 4000
     # out: {success:true,data:[{id,name,status:"idle"|"running"|"waiting_user"|"error",memberCount,hasWaitingUser,waitingCount?,leadAppId,localMembers:[{appId,memberName,isLead}],hostNodeId?,updatedAt}]}
     # note: Optional query: ?spaceId=. Omitting it lists every space, which is what the Halo app shows; pass $HALO_SPACE_ID to narrow it, and say which of the two you did.
     # note: Only saved teams appear in this directory. Work inside a conversation is managed through its current collaboration tools.
     # note: hostNodeId set means the team is hosted on someone else's computer and was joined from here — it can be read and its members messaged, but not edited or run.

POST   /api/teams                                                  Create a persistent team, with a lead provisioned for it
     # note: reversible — can be undone or corrected afterward.
     curl -sX POST "$HALO_API_URL/api/teams" \
          -H "Authorization: Bearer $HALO_API_TOKEN" \
          -H "Content-Type: application/json" \
          -d '{"input":{"name":"Weekly market brief","goal":"Every Monday, summarise competitor moves into brief.md","owningSpaceId":"<spaceId — a uuid from GET /api/spaces>","memberSourcing":"manual","collabMode":"free","escalationRouting":"user","members":[{"appId":"<appId — a digital human from GET /api/apps>","memberName":"Researcher","role":"Research","duty":"Collects competitor news"}]}}'
     # body: {"input": {"name": "Weekly market brief", "goal": "Every Monday, summarise competitor moves into brief.md", "owningSpaceId": "<spaceId — a uuid from GET /api/spaces>", "memberSourcing": "manual", "collabMode": "free", "escalationRouting": "user", "members": [{"appId": "<appId — a digital human from GET /api/apps>", "memberName": "Researcher", "role": "Research", "duty": "Collects competitor news"}]}}
     # out: {success:true,data:{id,name,owningSpaceId,goal,leadAppId,memberSourcing,collabMode,escalationRouting,status,currentEpochId,createdAt,updatedAt}}
     # note: memberSourcing "manual": members are existing digital humans (appId from GET /api/apps). memberSourcing "ai": omit members and send "confirmedProposal": [{memberName, role, responsibility}] (up to 5) beside "input" — POST /api/teams/propose-members drafts one; Halo creates a new digital human for each.
     # note: collabMode: "free" (members contact anyone) or "structured" (edges are generated from the lead; edit them with PUT /api/teams/:teamId/edges). escalationRouting: "user" (questions go to the user) or "lead".
     # note: Creates digital humans (the lead, and AI-sourced members) as a side effect; on any failure the whole team is rolled back.
     # note: Create a persistent team only when the user asked for one. Members' delegated permissions are set in the Halo app — see this page's withheld list.

GET    /api/teams/<teamId>/chat-messages                           Read one member's transcript in one team conversation
     curl -s "$HALO_API_URL/api/teams/<teamId>/chat-messages?appId=<appId — a member appId from GET /api/teams/:teamId/detail>&epochId=<epochId — a conversation from GET /api/teams/:teamId/conversations>" -H "Authorization: Bearer $HALO_API_TOKEN" | tail -c 4000
     # out: {success:true,data:[messages],stale?:true}
     # note: epochId is required and is never chosen for you; without it the call fails with code halo.team.conversation_required and lists recent conversations as candidates. Optional query: &sinceSeq= for incremental reads.
     # note: A member on another computer is fetched from its owner; stale:true means a cached copy because the owner is offline, and a 502 means it is unavailable right now.

POST   /api/teams/<teamId>/members/<appId>/send                    Send a message to one team member in one conversation and wait for its reply
     # note: reversible — can be undone or corrected afterward.
     curl -sX POST "$HALO_API_URL/api/teams/<teamId>/members/<appId>/send" \
          -H "Authorization: Bearer $HALO_API_TOKEN" \
          -H "Content-Type: application/json" \
          -d '{"message":"Please re-check the pricing section","epochId":"<epochId — a conversation from GET /api/teams/:teamId/conversations>"}'
     # body: {"message": "Please re-check the pricing section", "epochId": "<epochId — a conversation from GET /api/teams/:teamId/conversations>"}
     # out: {success:true,data:{ok,finalMessage,reason?,delivery?:"queued"|"mid_turn"}}
     # note: epochId is required: the message lands in that conversation and no other is chosen for you. Pick it by label; if more than one could be meant, ask the user using the labels. Without it the call fails with code halo.team.conversation_required and lists recent conversations as candidates.
     # note: Sending into a conversation marked completed reopens it — ask the user first. A member with no conversation yet: open one with POST /api/teams/:teamId/conversations, then send into it. Pass memberAppId there only for a member on this computer: naming one whose origin is "remote" in GET /api/teams/:teamId/detail is refused, so for such a member open the conversation without it.
     # note: Blocks until the member finishes its turn (can take minutes) and returns its final message. delivery "queued"/"mid_turn" means the member was busy: the message was accepted but no reply exists yet — read it later with GET /api/teams/:teamId/chat-messages. ok:false with reason UNDELIVERED means it never arrived; reason CONVERSATION_NOT_FOUND means that epochId is not a conversation of this team — list conversations again. Works for members on other computers too.

POST   /api/teams/<teamId>/run                                     Start independent work with a standing team
     # note: reversible — can be undone or corrected afterward.
     curl -sX POST "$HALO_API_URL/api/teams/<teamId>/run" \
          -H "Authorization: Bearer $HALO_API_TOKEN" \
          -H "Content-Type: application/json" \
          -d '{"instruction":"Investigate the current issue","trigger":{"type":"manual"}}'
     # body: {"instruction":"Investigate the current issue","trigger":{"type":"manual"}}
     # out: {success:true,data:{epochId}} — the accepted work continues in the background
     # note: instruction is this work’s brief. When omitted, the standing goal is used; a team with no standing goal requires an instruction.
     # note: Explicit manual work may run concurrently. Without trigger.type="manual", HTTP-triggered work keeps the automatic no-overlap guard.
     # note: Use the returned epochId to follow this work. Do not infer it from a team’s current/latest pointer. Temporary collaborations and teams hosted elsewhere cannot be started through this route.
