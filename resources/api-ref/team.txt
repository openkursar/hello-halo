## team — teams of digital humans that work toward one goal together
covers: list, create and dissolve teams, edit name and goal, add, remove and
        re-brief members, collaboration topology, start and stop a run,
        schedules and other triggers, message or stop one member, run history,
        boards, conversations and produced files, save a temporary
        collaboration as a team
not here:
  one digital human on its own schedule -> digital-human
  installing a digital human to use as a member -> digital-human
  binding an IM chat to a team member -> channels
  assembling a temporary team inside this conversation -> use the collab_start tool

GET    /api/teams                                                  List teams, optionally only those owned by one space
     curl -s "$HALO_API_URL/api/teams" -H "Authorization: Bearer $HALO_API_TOKEN" | head -c 4000
     # out: {success:true,data:[{id,name,status:"idle"|"running"|"waiting_user"|"error",memberCount,hasWaitingUser,waitingCount?,leadAppId,localMembers:[{appId,memberName,isLead}],hostNodeId?,ephemeral?,updatedAt}]}
     # note: Optional query: ?spaceId=. Omitting it lists every space, which is what the Halo app shows; pass $HALO_SPACE_ID to narrow it, and say which of the two you did.
     # note: ephemeral:true is a temporary collaboration started from a conversation; it is hidden from the Teams page until saved (POST /api/teams/:teamId/save-collab).
     # note: hostNodeId set means the team is hosted on someone else's computer and was joined from here — it can be read and its members messaged, but not edited or run.

POST   /api/teams                                                  Create a persistent team, with a lead provisioned for it
     # note: reversible — can be undone or corrected afterward.
     curl -sX POST "$HALO_API_URL/api/teams" \
          -H "Authorization: Bearer $HALO_API_TOKEN" \
          -H "Content-Type: application/json" \
          -d '{"input":{"name":"Weekly market brief","goal":"Every Monday, summarise competitor moves into brief.md","owningSpaceId":"<spaceId — a uuid from GET /api/spaces>","memberSourcing":"manual","collabMode":"free","escalationRouting":"user","members":[{"appId":"<appId — a digital human from GET /api/apps>","memberName":"Researcher","role":"Research","duty":"Collects competitor news"}]}}'
     # body: {"input": {"name": "Weekly market brief", "goal": "Every Monday, summarise competitor moves into brief.md", "owningSpaceId": "<spaceId — a uuid from GET /api/spaces>", "memberSourcing": "manual", "collabMode": "free", "escalationRouting": "user", "members": [{"appId": "<appId — a digital human from GET /api/apps>", "memberName": "Researcher", "role": "Research", "duty": "Collects competitor news"}]}}
     # out: {success:true,data:{id,name,owningSpaceId,goal,leadAppId,memberSourcing,collabMode,escalationRouting,status,currentEpochId,createdAt,updatedAt}}
     # note: memberSourcing "manual": members are existing digital humans (appId from GET /api/apps). memberSourcing "ai": omit members and send "confirmedProposal": [{memberName, role, responsibility}] (up to 5) beside "input" — POST /api/teams/propose-members drafts one; Halo creates a new digital human for each.
     # note: collabMode: "free" (members contact anyone) or "structured" (edges are generated from the lead; edit them with PUT /api/teams/:teamId/edges). escalationRouting: "user" (questions go to the user) or "lead".
     # note: Creates digital humans (the lead, and AI-sourced members) as a side effect; on any failure the whole team is rolled back.
     # note: Create a persistent team only when the user asked for one. Members' delegated permissions are set in the Halo app — see this page's withheld list.

Halo does all of these; you do not. Say so, and say where:
  - Invite people from other computers into a team, revoke an invite, or join a team hosted on someone else's computer — each one decides who can reach this machine, so the user does it from the team's settings in the Halo app.
  - Set what teammates on other computers may make a member do (its delegated permissions) — that is the owner's consent for their own machine, set from the member's settings in the Halo app. Member and team writes refuse the delegatedPolicy field for that reason.
  - Add, change, pause or resume a webhook trigger — it lets anyone who can reach this computer start the team with the owner's permissions, so the trigger write refuses sourceType webhook. Tell the user this is something you cannot set up for them, and offer a schedule or file trigger if one fits.
